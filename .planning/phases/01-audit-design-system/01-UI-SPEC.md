# Phase 1 — UI Design Contract

> Visual and interaction contract for the Audit & Design System phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Cardinal constraint (CONTEXT D-02, D-05):** every value below is **extracted from the app as actually rendered** (light theme). This is harmonisation, not rebranding — screens must stay pixel-identical. The tokens and master components (`src/ui/`) codify existing patterns; they do not invent new ones.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | **none** — native Tailwind v4 (CSS-first `@theme`), no shadcn |
| Preset | not applicable |
| Component library | **none** — custom master components in `src/ui/` (Button, Card, Input, Modal, Header) per D-04 |
| Icon library | **Lucide React** (existing convention) |
| Font | **DM Sans** (base body, `:root`) — ⚠️ conflicts with `@theme --font-sans: Inter`; audit must canonicalise on the rendered face (D-02) |

**Why Tool: none.** Upstream decisions D-01/D-04/D-05 lock the design system to a native Tailwind v4 `@theme` token source plus a hand-built `src/ui/` library extracted from the existing app. Introducing shadcn (Radix + its own theming/visual language + new dependency) would contradict the "no rebranding / appearance unchanged" mandate. The shadcn initialisation gate is therefore answered **no by upstream decision** — not re-asked. Registry safety gate: **not applicable**.

**Single token source (D-01):** `src/index.css` `@theme` block, cleaned and canonicalised. Tailwind v4 generates utilities (`bg-primary`, `rounded-xl`, …) directly from it. No extra indirection layer. JS-consumed colours (e.g. `Map.tsx` markers) must reference the same source values (D-03), migration of the map itself deferred to Phase 2.

## Spacing Scale

First-class tokens are the standard 4-point set (4, 8, 16, 24, 32, 48) — all extracted from real usage. Dominant classes: `p-4` (48×), `gap-2` (43×), `p-6` (20×), `p-8`, plus the off-scale `gap-3`/`p-3`/`py-3` (27×) captured as an exception below.

| Token | Value | Usage (extracted) |
|-------|-------|-------------------|
| xs | 4px | Icon gaps, tight inline (`p-1`, `gap-1`) |
| sm | 8px | Compact spacing, field label gap (`gap-2`, `p-2`, `space-y-2`) |
| md | 16px | Default element / container padding (`p-4`) |
| lg | 24px | Card / section padding (`p-6`) |
| xl | 32px | Modal padding, major section breaks (`p-8`) |
| 2xl | 48px | Page-level vertical rhythm (`py-12`) |

Exceptions:
- **12px (`gap-3` / `p-3` / `py-3`) — declared exception, NOT a first-class scale token.** It is a multiple of 4 but is **not** a member of the standard spacing set (4, 8, 16, 24, 32, 48, 64), so it is intentionally excluded from the scale table above. It is extracted from the dominant existing usage (**27× `gap-3`/`p-3`**): form-field gaps and input/button vertical padding. It is retained **verbatim** solely to preserve pixel-identical rendering per the phase's cardinal constraint (CONTEXT D-02/D-05: harmonisation, not rebranding). **Do NOT normalise it to 8px or 16px** — doing so would change rendered spacing and violate the pixel-identical mandate. The Input and Button master components consume this value at its existing size; it is not offered as a general-purpose spacing choice for new layout.
- **Input font-size locked at 16px** globally (`input, textarea, select`) to prevent iOS focus-zoom — do not override in the Input master component.
- **AuthModal outer radius `rounded-[32px]`** is a hard-coded non-token value — reconcile into the **radius** scale as `2xl = 32px` during token extraction (radius, not spacing).

## Radius & Elevation

Part of DS-01 token scope (radius + shadows). Extracted from real usage — `rounded-xl` (70×) is the workhorse; `shadow-sm` (15×) and `shadow-2xl` (11×, modals) dominate.

| Radius token | Value | Usage |
|--------------|-------|-------|
| sm | 8px | `rounded-lg` — small chips, compact controls |
| md (default) | 12px | `rounded-xl` — inputs, buttons, error banners |
| lg | 16px | `rounded-2xl` — cards |
| xl | 24px | `rounded-3xl` — large surfaces |
| 2xl | 32px | Modal surface (reconciles AuthModal `rounded-[32px]`) |
| full | 9999px | Pills, avatars, icon-only buttons (`rounded-full`) |

| Elevation token | Value | Usage |
|-----------------|-------|-------|
| sm | `shadow-sm` | Subtle resting cards |
| lg | `shadow-lg` | Primary buttons, with coloured glow `shadow-sky-500/20` |
| 2xl | `shadow-2xl` | Modals / overlays |

**Glass-morphism (codify verbatim, D-05):**
- Modal surface: `bg-white/10 backdrop-blur-xl border border-white/20`
- Modal backdrop: `bg-black/60 backdrop-blur-md`
- Light glass card: `rgba(255,255,255,0.7)` bg, `rgba(255,255,255,0.5)` border (`--glass-bg` / `--glass-border`)

## Visual Hierarchy & Accessibility

**Primary visual anchor — AuthModal proof screen (D-09).** The single dominant focal point is the **primary CTA submit Button** (`primary` variant: `bg-sky-500` accent fill, `shadow-lg` with `shadow-sky-500/20` glow). It is the only accent-coloured, elevated, full-width element on the screen; the reading/interaction hierarchy flows **modal heading → input fields → primary CTA**. The dark-glass modal surface is the containing frame, not the anchor. During migration the executor must preserve this hierarchy exactly: the sky-500 primary Button stays the sole visual anchor — do not flatten it to match secondary/ghost buttons and do not introduce a second accent-coloured competing element.

**Icon-only button accessibility.** Icon-only buttons (`rounded-full`, referenced in the Radius section) carry no visible text label and therefore **require an `aria-label` (or `sr-only` text) per the Button master component contract**. The Button component must accept and forward an accessible-label prop, and must not render an icon-only variant without one. This applies to every icon-only control migrated in this phase and to future consumers of the master Button.

## Typography

Extracted roles. Sizes: `text-sm` (14) is the body workhorse, `text-xs` (12) labels, `text-2xl` (24) headings, 16px inputs/buttons (base). Weights: `font-bold` (700, 117×) + base `400`.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 700 (bold, uppercase, tracking-wider) | 1.2 |
| Body | 14px | 400 | 1.5 |
| Input / Button | 16px | 400 body / 700 button | 1.5 |
| Heading | 24px | 700 | 1.2 |

**Weights (2):** `400` regular (body/base) + `700` bold (labels, headings, buttons). ⚠️ `font-medium` (500, 42×) exists elsewhere in the app; it does not appear on the AuthModal proof screen. Consolidate 500→400/700 in later screen migrations (Phases 2–4), not in this phase — Phase 1 targets only the token file, the `src/ui/` library, and AuthModal, which already resolve to 400/700.

## Color

App renders in **light theme** (`color-scheme: light`, background `#f8fafc`). The "Deep Ocean" dark palette in the current `@theme` block is residual/dead and must be pruned during canonicalisation (D-02). Glass modals render dark-glass surfaces with white text over the light app.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f8fafc` (Slate 50) | Page background, light surfaces |
| Secondary (30%) | `#ffffff` glass cards + `#0f172a` (Slate 900) dark-glass surfaces; text `#1e293b` (Slate 800) / `#64748b` (Slate 500) muted | Cards, nav, modal surfaces, body & muted text |
| Accent (10%) | `#0ea5e9` (Sky 500) | See reserved list |
| Destructive | `#f43f5e` (Rose 500) / `red-500` | Error banners, destructive/delete confirmations |

Accent reserved for: **primary CTA buttons** (`bg-sky-500`), **focus rings** (`ring-sky-500`), **active nav / tab state**, and **interactive links & highlighted icons** (`text-sky-500/600`). Never applied to plain body text, borders of static cards, or decorative surfaces.

## Copywriting Contract

Phase 1 ships no new user-facing screens — it delivers the token file, the `src/ui/` library, and a **pixel-identical migration of `AuthModal`** (D-09). All copy is inherited from the existing i18n keys and must stay unchanged. No new strings are invented.

| Element | Copy |
|---------|------|
| Primary CTA | AuthModal submit — existing keys `auth.btn_login` / `auth.btn_signup` (unchanged) |
| Empty state heading | Not applicable this phase (no data views migrated). Empty-state pattern lands in Phases 2–4. |
| Empty state body | Not applicable this phase |
| Error state | AuthModal keeps `mapAuthError` → existing keys: `error.invalid_credentials`, `error.email_exists`, `error.weak_password`, `error.generic` (unchanged). Displayed in a `rounded-xl bg-red-500/20 border border-red-500/30 text-red-200` banner. |
| Destructive confirmation | None in Phase 1. Button exposes a `danger` variant (D-06) for future use, but no destructive action is wired this phase. |

**Master component copy contract (for the library, not screens):** component labels are consumer-supplied props — the library ships no hard-coded copy. Button variants: `primary / secondary / ghost / danger`, sizes `sm / md / lg`, states `loading / disabled` (D-06). Variants extend the API only, never the appearance.
